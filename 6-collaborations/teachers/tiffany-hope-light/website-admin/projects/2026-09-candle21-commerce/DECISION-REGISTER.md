# 21 顆蠟燭 commerce｜決策登錄

狀態：**給 mamasan QC／QA 的工程草稿，不代表 Tiffany 已核准。**

本案的基本立場：**能做成後台欄位的，就不要做成問題。** 售價、庫存、含運、贈品與款名
都以目前 LP 的值出廠，並全部交給 Tiffany 在 wp-admin 自己改；她要調整時不必經過我們。
只有「做成欄位也解決不了」的事才留在下面的待決清單。

## 已採用的工程預設

這些預設可讓藍圖與本機實作前進；若 mamasan／Tiffany 不同意，應在施工前改掉。

| ID | 預設 | 理由 |
|---|---|---|
| C21-P01 | LP 提供「直接訂購」與「先諮詢」兩個入口 | 同時服務已確定與未確定選款者 |
| C21-P02 | 先諮詢者在諮詢後才回 WooCommerce 選款結帳 | MVP 不建立「已付款但選款未完成」的半張訂單 |
| C21-P03 | 直接訂購時，十款數量須為非負整數且合計恰好 21 | 避免人工重新確認基本配置 |
| C21-P04 | WooCommerce 是價格、付款、地址、訂單與配置的正式主檔 | 延續 D-001 與 D-003，不造第二本帳 |
| C21-P05 | CRM 維持唯讀，只顯示蠟燭配置、來源與諮詢路徑 | 不擴大後台寫入面與個資風險 |
| C21-P06 | LINE MVP 使用關鍵字自動回應與一般 HTTPS 連結 | 不為首版引入 Messaging API／LIFF 維運負擔 |
| C21-P07 | 每個公開入口使用明確 source code／UTM | 不靠容易遺失的 referrer 猜訂單來源 |
| **C21-P08** | **營運參數（售價、庫存、含運、贈品、款名、諮詢說明）一律做成 Tiffany 可自助修改的後台欄位，且是唯一事實來源** | 老師只在意 UI 好不好用；把參數變成欄位，等於一次解決往後所有的來回確認 |
| **C21-P09** | **LP 移入 WordPress 子佈景主題頁面範本，商業數字改用短碼輸出** | C21-P08 的必要條件。LP 停在靜態 Artifact，就無法跟著後台變動 |

## 以預設出廠、Tiffany 可自助修改（不擋施工）

以下項目**不需要事前回覆就能開工**。出廠值取自目前 LP，上線後她在後台自己調整。

| ID | 項目 | 出廠值 | 她之後在哪裡改 |
|---|---|---|---|
| C21-A01 | 21 顆組售價 | NT$2,980 | Woo 商品 → 一般 → 售價 |
| C21-A02 | 全台含運 | 含運 | Woo → 運送設定 |
| C21-A03 | 玻璃燭台贈品 | 附 1 個 | 外掛設定頁 →「組合內容」，可整項關閉 |
| C21-A04 | 首批組數與售罄規則 | 由 Woo 商品庫存控制 | Woo 商品 → 庫存 |
| C21-A05 | 10 分鐘諮詢的次數與使用期限 | 每筆一次，購買後 30 天內 | 外掛設定頁 →「諮詢」 |
| C21-A06 | 十款顯示名稱與描述 | 同 `product-facts.md` 現行款名 | 外掛設定頁 →「十款」 |

**一次性告知，不需回覆**：21 × 139 = 2,919，限定組 2,980，差額 61 元要涵蓋運費、
燭台與 10 分鐘諮詢。完整成本推算見 [`product-facts.md`](../../../product-facts.md)
的〈21 顆組：已確認與待確認〉。這一段保留是為了讓 Tiffany 知道有這個欄位可以調，
不是要她先答覆才准施工。
