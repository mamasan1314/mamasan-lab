# CRM、WooCommerce、Airtable 與網站工具白話說明

文件狀態：`v0.1｜給 mamasan 核對的白話草稿`  
日期：`2026-08-27（Asia/Taipei）`  
閱讀程度：`國二生可理解`  
目前狀態：`只是在說明名詞，並不表示 Airtable 或同步已經上線`

## 先用一家店來想像

把希望之光想成一家店：

- **HopeBox 網站**是店面。
- **Elementor 表單**是門口的登記櫃台。
- **Elementor Submissions**是櫃台後面的收件匣。
- **WooCommerce**是收銀台、訂單簿和出貨單。
- **CRM**是店裡的顧客筆記本。
- **Airtable**是拿來做這本顧客筆記的工具。
- **預約系統**是老師的行事曆。
- **Webhook**像門鈴：有人填表或下單時，立刻通知另一個系統。
- **API**像有規則的跑腿員：只能依照允許的方式拿資料或送資料。

所以不是每個工具都做所有事情。每個工具把自己最擅長的部分做好，資料才不會亂。

## 這次資料怎麼走

```text
客人填小貴人登記表
        ↓
網站留一份原始表單
        ↓
Airtable 建立顧客與待辦
        ↓
客人到 WooCommerce 結帳付款、填地址
        ↓
如果要 10 分鐘諮詢，再進預約流程
```

已有的 WooCommerce 顧客也可以整理進 Airtable，但現在還沒有開始。第一次會先預覽、找重複，再由 mamasan 核對後匯入。

## 名詞翻譯

### CRM

英文是 Customer Relationship Management，中文常翻成「顧客關係管理」。

白話說：**一本會提醒你下一步的顧客筆記本。**

它不只記姓名和電話，還會記：

- 這個人從哪裡來？
- 想買什麼？
- 有沒有付款？
- 誰要聯絡他？
- 下次什麼時候再聯絡？
- 有沒有預約諮詢？

在本案中，CRM 是一種工作方法；我們建議用 Airtable 來實作，但 CRM 不等於 Airtable。

### Airtable

Airtable 是一種線上資料工具。外觀看起來像試算表，但不同表格可以互相連結，也可以做簡單的自動提醒和工作畫面。

白話說：**比 Excel 更會互相連線的線上顧客筆記本。**

例如，一位客人可以同時連到：

- 一筆小貴人活動登記
- 兩張不同訂單
- 一次 10 分鐘諮詢
- 三次聯絡紀錄

重要提醒：Airtable 是外部雲端服務。帳號、權限、付費方式及個資規則需要先決定。目前希望之光尚未建立或連線 Airtable。

### WooCommerce

WooCommerce 是 WordPress 網站裡的開店系統。

白話說：**網站裡的收銀台＋訂單簿＋出貨單。**

它主要負責：

- 商品與價格
- 購物車和結帳
- 付款狀態
- 收件姓名、電話和地址
- 訂單、取消、退款與出貨狀態

因此完整地址應該以 WooCommerce 為準，不需要再到 Airtable 手動改一次。

### WordPress

WordPress 是 HopeBox 網站的主要系統。

白話說：**整間網路店面的建築物。**

Elementor、WooCommerce 和其他外掛，都裝在這棟建築物裡工作。

### Elementor

Elementor 是 WordPress 裡用來做網頁的工具。

白話說：**不用從零寫程式，也能排版網頁和做表單的裝潢工具。**

這次可以用它做小貴人專屬登記頁。

### Elementor Submissions

這是 Elementor 保存表單內容的後台頁面。

白話說：**櫃台後面的原始收件匣。**

它可以確認客人當時填了什麼，但不適合拿來管理 400 個人的聯絡進度，因此仍需要 CRM。

### 表單 Form

表單就是讓客人填資料的網頁。

白話說：**數位版的登記紙。**

表單負責收資料，不等於訂單，也不一定代表已經付款或保留到庫存。

### 資料庫 Database

資料庫是把資料按照規則保存的地方。

白話說：**有編號、有分類的資料櫃。**

如果只是把很多資料全部丟在備註欄，就像把所有紙張塞進同一個抽屜，以後很難找。

### 資料表 Table

資料表是一類相同資料的集合。

白話說：**資料櫃裡的一個抽屜。**

例如：

- 顧客表只放「人」
- 訂單表只放「訂單」
- 諮詢表只放「預約」

### 欄位 Field

欄位是一項固定問題或資料。

白話說：**表格最上方的欄目名稱。**

例如姓名、電話、付款狀態、下一次聯絡日，都是不同欄位。

### 紀錄 Record

紀錄是資料表裡的一筆資料。

白話說：**表格裡的一整列。**

顧客表的一列通常是一位顧客；訂單表的一列通常是一張訂單。

### 顧客 ID／唯一 ID

ID 是每筆資料專用、不重複的編號。

白話說：**資料的身分證號，但它不是客人的真正身分證字號。**

兩個人可能同名，但顧客 ID 不會相同。系統靠 ID 知道哪張訂單屬於哪位顧客。

### SKU

SKU 是商品的內部編號。

白話說：**商品的身分證號。**

例如大小貴人若有不同版本，就應該有不同 SKU，避免價格、庫存和出貨拿錯。

### 訪客結帳 Guest Checkout

有些客人沒有註冊網站會員，也能直接下單。

白話說：**客人有買東西，但沒有辦會員卡。**

因此只看 WooCommerce 的顧客帳號會漏人，還要查看訂單。

### 匯入 Import

匯入是把舊系統的資料搬到新系統。

白話說：**把舊筆記本整理後抄進新筆記本。**

正式匯入前要先預覽，避免重複、搬錯或把不相關資料一起帶進去。

### 同步 Sync

同步是讓兩個系統的指定資料保持一致。

白話說：**一本帳更新後，另一個工作看板也跟著更新。**

本案建議先做單向同步：WooCommerce 把訂單狀態送給 Airtable；不要讓 Airtable 反過來改付款或地址。

### Webhook

Webhook 是一個系統在事情發生時，主動通知另一個系統。

白話說：**門鈴。**

客人一填表，門鈴就響，CRM 知道要建立新登記；不用一直派人問網站「有沒有人填表」。

### API

API 是兩套系統交換資料時共同遵守的規則。

白話說：**有工作證、照規定拿送資料的跑腿員。**

API 不是一個人，也不是一份顧客名單。它只是讓程式知道可以拿什麼、怎麼拿。

### Token／API Key

Token 或 API Key 是系統辨認身分用的秘密字串。

白話說：**機器使用的鑰匙。**

它不能放在公開網頁、聊天、Git 或教學文件裡，否則別人可能拿這把鑰匙讀寫資料。

### Plugin／外掛

外掛是在原本系統上增加功能的小程式。

白話說：**替店面加裝的新設備。**

WooCommerce 本身就是 WordPress 外掛。外掛裝得越多，不一定越好；還要考慮安全、維護和互相衝突。

### Automation／自動化

自動化是事先設定好「發生 A，就執行 B」。

白話說：**照規則工作的自動小助手。**

例如：

- 有人填表 → 建立 Airtable 登記
- 訂單已付款 → 建立出貨待辦
- 顧客需要諮詢 → 建立排程任務

自動化仍要有錯誤提醒，不能假設它永遠不會失敗。

### 去重 Deduplication

去重是找出重複資料，判斷是否為同一人。

白話說：**確認「王小明」和「小明」是不是同一位客人。**

不能只看姓名，通常還要比對 Woo 顧客 ID、Email、手機；不確定時交給人工確認。

### Source of Truth／正式主檔

正式主檔是發生矛盾時，以哪一套系統為準。

白話說：**最後要相信的那一本帳。**

本案建議：

- 付款、地址、出貨：相信 WooCommerce
- 原始填表內容：相信 Elementor Submissions
- 顧客聯絡進度：相信 Airtable
- 預約日期與時間：相信預約系統

### 狀態 Pipeline

Pipeline 是把工作分成一個個階段。

白話說：**看包裹現在走到哪一站。**

例如：新登記 → 待付款 → 已付款 → 待出貨 → 已出貨 → 結案。

### 對帳 Reconciliation

對帳是定期比較兩邊資料是否一致。

白話說：**每天關店前，確認收銀台和工作筆記有沒有漏掉同一張訂單。**

即使有自動同步，也應該定期對帳。

### 權限 Permission

權限是決定誰能看、誰能改、誰能刪除資料。

白話說：**每個人拿到不同房間的鑰匙。**

只需要處理聯絡的人，不一定要看到完整地址；只需要看待辦的人，也不一定能匯出全部顧客資料。

### 備份 Backup

備份是多留一份可以復原的資料。

白話說：**重要筆記不能只放在唯一一本本子裡。**

但備份也含有個資，因此一樣需要權限和保存期限。

### 個人資料／個資

可以直接或間接認出一個人的資料，都可能是個資。

白話說：**能讓別人知道「這是誰」的資訊。**

姓名、電話、Email、IG、地址、生日都可能是個資。不要因為「以後也許用得到」就全部蒐集。

### 行銷同意

行銷同意是客人清楚表示願意收到未來的促銷或活動訊息。

白話說：**客人有說「以後也可以傳活動給我」。**

填表、買過商品或曾在 IG 留言，不等於永久同意接收行銷；這個選項應該和本次訂單需要的聯絡分開。

## 常見問題

### Airtable 會取代 WooCommerce 嗎？

不會。WooCommerce 繼續管訂單、付款、地址和出貨；Airtable 只把各處的重點整理成工作看板。

### 目前 WooCommerce 的舊顧客已經進 Airtable 了嗎？

還沒有。目前 Airtable 尚未建立或連線。未來會先做唯讀盤點、去重預覽，經 mamasan 核對後才匯入。

### 為什麼不把地址一起放進 Airtable？

因為地址已經在 WooCommerce，而且是較敏感的資料。多複製一份，就多一個可能外洩、過期或改錯的地方。

### 為什麼不能只用 Excel？

Excel 可以做規劃和小量管理，但 400 筆表單、歷史訂單、聯絡任務和狀態更新若全靠人工，很容易漏件、重複或版本不同。現有 Excel 草稿仍可當作欄位設計參考。

### Tiffany 一定要學會看全部 Airtable 嗎？

不一定。可以做一個簡化畫面，只顯示今天要聯絡誰、誰待付款、誰待出貨、誰要排諮詢。是否開放哪些資料，由 mamasan 決定。

### 系統有自動化後，就不用人工檢查了嗎？

不是。自動化可以減少重複工作，但仍要有錯誤提醒、每日或定期對帳，以及遇到同名或資料衝突時的人工判斷。

### 客人買過東西，就可以一直傳廣告嗎？

不應這樣假設。完成訂單所需的聯絡和未來行銷是不同用途；沒有清楚紀錄時，行銷同意應標為「未知／未取得」。

## 最後只記住四句話

1. **Elementor 收表單。**
2. **Airtable 管顧客進度。**
3. **WooCommerce 管訂單、付款和地址。**
4. **預約系統管老師的時間。**

如果兩邊資料不一樣，就回到各自的正式主檔確認，不要靠印象猜。
